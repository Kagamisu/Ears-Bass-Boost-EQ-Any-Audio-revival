# Откуда код и что с лицензиями

Заметки от 27 октября 2026 по файлам сохранённой Ears. Они описывают то, что удалось найти, и не подтверждают всю цепочку прав на проект.

## Что известно

Автором в исходном manifest указан **Kevin King**. У собственных bg.js, popup.js, HTML/CSS и графики в архиве не было разрешающей лицензии. Отдельные права на название Ears и иконки тоже не установлены; поиск по товарным знакам не проводился.

Контакт из старого popup — `4kevinking@gmail.com`. Актуальность адреса не проверялась, писем туда не отправлялось. Поиск по автору и названию не нашёл разрешающую лицензию на эти части, но это не доказывает, что её нигде нет.

Новая MV3-часть, тесты и инструменты написаны для Revival. На перечисленные в [LICENSE.md](../LICENSE.md) новые файлы распространяется MIT. Эта лицензия не выдаёт прав на оставшийся старый UI и графику.

У Snap.svg 0.4.1 — Apache-2.0. Официальный NOTICE также указывает Apache-2.0 для Eve. Оригинальные уведомления сохранены, удаление AJAX-транспорта отмечено в начале изменённого файла. Полный текст лицензии и upstream NOTICE лежат в [extension/LICENSES](../extension/LICENSES). Перечисленные в NOTICE dev/demo-зависимости upstream в само расширение не включены.

Источники библиотеки: [NOTICE v0.4.1](https://github.com/adobe-webplatform/Snap.svg/blob/v0.4.1/NOTICE), [репозиторий Snap.svg](https://github.com/adobe-webplatform/Snap.svg), [Apache-2.0](https://www.apache.org/licenses/LICENSE-2.0).

## Чего из этого не следует

Отсутствие лицензии в архиве не делает код общественным достоянием. Перекраска, перенос на другой manifest и публикация на GitHub сами по себе тоже не меняют права на старые части. Об автоматической охране программ и использовании чужих работ есть пояснение у [WIPO](https://www.wipo.int/en/web/copyright/faq-copyright).

Revival сохраняет оригинальный интерфейс и не называется clean-room реализацией. Право на код не подтверждает автоматически право на иконки и название. Эти вопросы нужно проверять по компонентам; весь репозиторий одной лицензией MIT не помечен.

## Перед магазином

Нужно выяснить условия распространения оригинального кода, UI, графики и названия. Если права получены, подтверждения можно записать в `publication/rights-clearance.json`, а личные документы оставить вне репозитория. Если выбран другой путь, свои компоненты, название и графику всё равно стоит проверить отдельно.

Описание и скриншоты не должны выдавать Revival за официальный релиз Kevin King. Это предусмотрено и [правилами Chrome Web Store](https://developer.chrome.com/docs/webstore/program-policies/impersonation-and-intellectual-property).

Проверка `--public` в сборщике только напоминает о незакрытых пунктах. Она не проверяет юридическую силу документов. Старый publisher key в Revival не используется, доступа к исходной записи магазина у проекта нет.

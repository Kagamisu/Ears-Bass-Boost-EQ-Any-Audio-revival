## До GitHub / Chrome Web Store

1. Установить правообладателя оригинального кода и графики, получить письменное разрешение на изменение, публикацию, использование названия/иконок и дальнейшие обновления. Уточнить, допускается ли открытая лицензия на производную версию.
2. Если разрешения нет, публичную ветку делать с самостоятельно созданными компонентами и собственной графикой/названием. Сам факт переписывания кода не является автоматической правовой очисткой интерфейса и бренда. Текущая версия сохраняет оригинальный UI для личного использования и не объявляется clean-room реализацией.
3. Проверить всю metadata магазина, screenshot и описание; не заявлять официальное продолжение или одобрение автора без основания. Политика [Impersonation & Intellectual Property](https://developer.chrome.com/docs/webstore/program-policies/impersonation-and-intellectual-property) запрещает нарушения прав и ложную принадлежность.
4. Сохранить evidence прав, заполнить `publication/rights-clearance.json`, контакт сопровождающего и URL privacy policy. После этого отдельно собрать и проверить публичный пакет. Встроенный gate не является юридической экспертизой: он не даёт случайно выдать текущую личную сборку за очищенный публичный релиз.

Оригинальный `key` не использован: Revival получает отдельную идентичность. Публикация под оригинальным ID потребовала бы доступа к исходной записи издателя, которого у проекта нет.

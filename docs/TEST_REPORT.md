# Что проверялось

Проверки от 27 октября 2026. Машина — Windows 10 Pro, браузеры — **Яндекс 26.10.0.1854** и **Chrome 156.0.8078.48**, Playwright 1.62.1. Всё запускалось в отдельных тестовых профилях.

Основной перенос проверялся на 1.3.13. После смены палитры сценарий повторён для 1.3.14 — отдельно об этом написано [здесь](GITHUB_EDITION_TESTS.md).

## Что прошло в обоих браузерах

- Загрузка MV3-расширения, настоящий HTML5 audio → tabCapture → offscreen → Web Audio. Контекст работал на 48 кГц, FFT видел тестовые частоты.
- Bass Boost, общий gain, Reset, движение точек, Shift/Q и двойной клик.
- Сохранение и удаление пресета, экспорт и импорт старого JSON-формата. Повреждённый JSON показывал ошибку и не портил сохранённые данные.
- Визуализатор без накопления градиентов; освобождение analyser после закрытия панели.
- Две подключённые вкладки с общим EQ, отдельное отключение одной, закрытие исходной вкладки и восемь циклов Stop/Start. Лишних живых streams и фильтров в этих проверках не осталось.
- Обработка после закрытия интерфейса и принудительной остановки worker. После возврата worker список потоков восстанавливался.
- Сохранность фильтров и пресетов после перезапуска тестового профиля. Старые потоки после запуска не возобновлялись.

В наблюдаемых контекстах расширения было **0 JS exceptions и 0 внешних HTTP-запросов**.

## Звук

Использовался настоящий захват вкладки с HTML5-аудио, без fake media. Bass Boost прибавлял около 5 дБ на 80 Гц. Точные значения каждого прогона есть в JSON ниже.

Нативные фильтры сравнивались с запущенным исходным bg.js: 3 конфигурации, по 256 частот. Максимальное наблюдаемое отличие АЧХ после сглаживания — **0 дБ**. Это результат для проверенных конфигураций, не утверждение о побитовом совпадении всего тракта с драйвером.

В окончательных прогонах до воспроизведения тестовых тонов выход AudioContext переключался на беззвучный sink `none`. Перед повторным созданием контекста громкость источника обнулялась. Рабочее расширение таким тестовым переключением не пользуется и выводит звук обычным способом.

Фоновый прогон после закрытия панели: **60 секунд для 1.3.13**, ещё **5 секунд для 1.3.14**. Часовых прогонов пока нет.

## Что получилось проверить с интерфейсом

В Chrome открывался настоящий toolbar popup. В обоих браузерах через автоматизацию выполнялись drag/Shift-drag/double click в полном окне, импорт через file input и экспорт через download.

У Яндекса отладочный `Extensions.triggerAction` выдаёт доступ к вкладке, но не оставляет доступного popup target. Поэтому для него сценарий использует тот же `popup.html` в полном окне с привязкой к аудиовкладке. Открытие через обычную кнопку панели Яндекса не считается подтверждённым этим скриптом.

## Быстрые проверки и сборка

`npm test`: **8/8**. Проверяются manifest, нужные файлы, четыре разрешения, синтаксис JS, параметры и формат пресетов. Старые key/update_url/_metadata, аналитика, storage.sync, eval/new Function и сетевой отправитель в runtime отсутствуют. Невалидный импорт отклоняется до сохранения.

В 1.3.13 CSS сверялся по SHA-256 и был сохранён побайтно. В 1.3.14 поменялись два цвета; размеры и расположение элементов остались прежними. Хеши исходных файлов — [original-inventory.json](original-inventory.json), текущего runtime — [runtime-sha256.json](runtime-sha256.json).

Сборщик проверяет CRC архивов. Повторная сборка одинаковых файлов в одной среде Python/zlib давала одинаковые SHA-256. В установочном ZIP manifest находится в корне, dev dependencies и _metadata не входят. Отдельный `--public` отказывает при незаполненных пунктах проверки прав. Подробнее — [про сборку](BUILD_VERIFICATION.md).

## Где ещё нужна проверка

Полный набор YouTube/музыкальных сервисов, DRM/EME, реклама в плеерах, WebRTC и конкретные аккаунты отдельно не прогонялись. Не проверялись часовая работа, подробный heap profiling, необычные sample rate, Bluetooth, отказ и смена физического аудиоустройства, сон/пробуждение Windows. Короткий прогон и подсчёт nodes не доказывают отсутствие всех утечек.

После перезапуска тестовый скрипт снова вызывает `Extensions.loadUnpacked` по тому же пути. Он проверяет данные, но не доказывает, что обычный Яндекс всегда сам включит локальное расширение. Другие браузеры, магазинные обновления и длительное субъективное сравнение звучания тоже не проверены.

Для ручной проверки полезно открыть Ears обычной кнопкой Яндекса на своём плеере, попробовать фильтры и пресеты, оставить музыку на 15–30 минут, подключить вторую вкладку и отключить одну из них. Затем проверить Stop → EQ, штатную остановку захвата браузером, экспорт/импорт, полный перезапуск, смену вывода и сон/пробуждение. Версии браузера и найденные ошибки лучше записать вместе с шагами воспроизведения.

## Проверка интерфейса

В Chrome проверен настоящий toolbar popup и сохранён `chrome-toolbar-popup.png`. В обоих браузерах выполнены мышью браузерной автоматизации drag/Shift-drag/double click по исходным SVG-элементам полного окна, экспорт через download и импорт через file input. Снимки `chrome-controls.png` и `yandex-controls.png` показывают исходный интерфейс со спектром.

В Яндексе `Extensions.triggerAction` выдаёт доступ к вкладке, но не оставляет доступного отладчику popup target. Поэтому его UI проверялся в полном окне того же `popup.html` с привязкой к выбранной вкладке. Попытка дополнительного наблюдения через Windows UI не дала usable screenshot/tree: capture сообщил `FrameArrived timed out`, повторная accessibility-проверка вернула пустое дерево. Слепые клики не выполнялись. **Обычное открытие popup через физическую панель Яндекса остаётся отдельной ручной проверкой.**

## Границы проверки

- YouTube, реальные музыкальные сервисы, DRM/EME, реклама внутри плееров, WebRTC-звонки и конкретные учётные записи отдельно не проверены. Захват не зависит от DOM плеера, но браузер/DRM может запрещать его.
- Часовые прогоны, количественный heap profiling, смена физического устройства, Bluetooth, сон/пробуждение Windows и необычные sample rate не проверены. 60-секундный прогон и контроль числа live nodes/streams не доказывают отсутствие всех утечек.
- Отдельный сценарий отказа физического аудиоустройства не воспроизводился. Обработчики ошибок/track.ended реализованы, штатное закрытие вкладки и повторные подключения проверены.
- После перезапуска тестовый harness повторно вызывает `Extensions.loadUnpacked` по тому же пути, затем проверяет сохранность данных и отсутствие старых streams. Это не проверка политики автоматического включения расширения в обычном профиле Яндекса.
- Не тестировались остальные Chromium-браузеры, Firefox, Safari, публикация в магазине и обновление через магазин.
- Субъективное длительное прослушивание оригинала и Revival не проводилось. Совпадение проверенных АЧХ не заменяет такую оценку.

## Ручной сценарий перед публичным выпуском

1. Загрузить `extension` через Developer Mode в обычном Яндексе, закрепить значок, открыть popup на странице с музыкой. Проверить 11 точек, gain, кнопки и отсутствие ошибок в `browser://extensions`.
2. На умеренной громкости проверить Bass Boost, drag и Shift-drag, Reset. Проверить YouTube и нужный музыкальный сервис; не обходить запрет DRM/защиты.
3. Закрыть popup на 15–30 минут, переключать вкладки и воспроизведение/паузу. Подключить вторую аудиовкладку, отключить одну через Active Tabs, убедиться в сохранности другой.
4. Проверить Stop → обычный звук → EQ без перезагрузки; остановить захват штатной кнопкой браузера; повторно открыть Ears.
5. Сохранить и экспортировать пресет, закрыть браузер, снова включить локальное расширение, проверить настройки и импорт. Убедиться, что захват не начался автоматически.
6. Проверить смену аудиоустройства и сон/пробуждение. При сбое проверить освобождение tracks/контекста и повторное подключение через кнопку.
7. Зафиксировать версии, ошибки, долгий прогон и результаты. Для public build заполнить release review только после этих проверок и оформления прав.
